# 日本語 Study

A personal Japanese learning app. One HTML file, no build step, no dependencies, no server,
no account. Progress lives in your browser.

## Running it

**Just open it.** `dist/index.html` is the whole app — double-click it, or put it on any
static host. It works from `file://` and works offline (the Google font is the only network
request, and it falls back to a system Japanese face when it fails).

**Working on the source** needs a server, because ES modules will not load over `file://`:

```
npx serve src        # or: python3 -m http.server --directory src
node tools/build.js  # rebuild dist/ after any change
```

## What's in it

| | |
|---|---|
| Kana | 208 — full hiragana and katakana, base + dakuten/handakuten + yōon |
| Vocabulary | 191 beginner words (31 verbs with rule-derived て / plain / ない forms) |
| Counters | 9, with full 1–10 reading tables and irregular forms flagged |
| Kanji | 26, taught through the words that use them |
| Grammar | 33 points, through the plain form |
| Sentences | 187 controlled examples, each with a full kana reading |
| Lessons | 53, across four stages |
| Exercise types | 16 |
| Practice modes | 9 |

## How it's laid out

```
src/
  content/      the curriculum — pure data, no UI
    kana.js         generated by tools/gen-kana.js
    counters.js     counter tables; unpredictable readings listed, not generated
    vocabulary.js   word, reading, meanings, part of speech, register, usage notes
    kanji.js        readings, stroke counts, the vocabulary each kanji appears in
    grammar.js      pattern, explanation, the mistakes English speakers actually make
    sentences.js    Japanese, kana reading, translation, chunked for sentence building
    lessons.js      lesson order and the blocks each lesson is built from
  engine/       the learning system — no DOM
    romaji.js       kana → Hepburn, the single source of truth for every romaji string
    conjugation.js  て / plain / ない construction as rules; the verifier re-derives every form
    srs.js          spaced repetition, mastery, weak-area detection
    exercises.js    exercise generation for every concept type
    storage.js      persistence (localStorage today; swap this file to change that)
  ui/           screens and components
tools/
  gen-kana.js       regenerates the kana table systematically
  tag-sentences.js  completes each sentence's grammar tags from the forms it contains
  verify-content.js content QA — run this after touching any content file
  audit-sequence.js curriculum sequencing: required knowledge vs. acceptable exposure
  build.js          bundles src/ into dist/
  e2e.js            drives the real app in a real browser
  test-dist.js      same, against the bundled single file
```

**Adding curriculum means adding data.** A new lesson is an entry in `lessons.js`; new words
are entries in `vocabulary.js`. No UI code changes, and every exercise type picks the new
material up automatically.

## Checks

```
node tools/verify-content.js   # cross-references, readings, coverage — must exit 0
node tools/e2e.js              # full loop in Chromium, light + dark + mobile
node tools/test-dist.js        # the bundle, from file://
```

`verify-content.js` re-derives every romaji string from the kana engine and every て-form from
the conjugation rules, and compares both to what is stored. It also checks that every id
referenced anywhere exists, that a word's declared kanji list is both correct and complete,
that on'yomi are katakana and kun'yomi hiragana, that sentence chunks reassemble into the
sentence, that every kana and grammar point is introduced by some lesson, and **that no lesson shows an
example using a conjugated form whose rule it has not yet taught**. That last check found
thirteen ordering violations in the Stage 1 curriculum the day it was written.

Counter readings are the one thing that cannot be derived, so they get a different check: the
verifier encodes the euphonic pattern (1, 6, 8 and 10 geminate before k-, s-, t- and h-initial
counters, and h shifts to p) and rejects any table that departs from it — 一本 must be いっぽん,
六個 must be ろっこ. That catches transcription slips in exactly the data a rule cannot produce.

`audit-sequence.js` separates the two questions that matter for sequencing. **Exposure** — a
learner seeing a particle in an example before its own lesson — is normal and is listed on
every run. **Required knowledge** — anything the learner is asked to parse or produce — is
enforced at serve time: `sentenceReady()` in the exercise engine will not offer a sentence
until every grammar point and word in it has been taught. The audit then reports the opposite
risk, which is a grammar point arriving with too little usable material to practise on. Content also goes through an independent factual review before release — that pass
is what caught the wrong okurigana on 三, the に-with-time-words rule being stated in a form
that produces ×明日に, and five sentences using grammar the curriculum had not taught yet.

## Deliberate limitations

- **Audio is synthetic.** It uses the device's Japanese speech voice where one exists, and
  hides itself where one does not. No native recordings.
- **Progress is per-browser.** No sync, no account. Settings → Export writes a JSON file;
  Import reads it back.
- **No handwriting recognition, no pitch-accent training, no conversation practice yet.**
- **Casual speech exists but is thin** — seven casual sentences, all in Stage 3. The plain past
  is the missing piece.
- **A handful of examples show a particle slightly before its own lesson** (を and に in the
  first verb lesson, これ/この in the です lessons). Standard textbook practice, glossed in
  place, and listed on every verifier run so it stays a deliberate choice rather than drift.
- **Kanji are met inside words before the character gets its own lesson** — 水 appears as みず
  in Stage 0, 水 as a character in Stage 1. That is the vocabulary-first design working as
  intended, not a sequencing bug; the reading is always shown.

## What comes next

The plain **past** (食べた, 行った — the て-form with た) completes the conjugation set. After
that: the potential form (話せます, which people use far more than ことができます), 〜たり〜たり,
giving and receiving, and conditionals.
